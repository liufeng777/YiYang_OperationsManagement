## 任务1：401 失效改为「先提示、延迟数秒后再跳转登录页」

### 任务描述

- 用户反馈：接口返回 401（未登录 / token 失效）时，`src/utils/request.ts` 直接 `window.location.href = '/login'` 整页刷新到登录页，没有任何提示，用户不知道发生了什么。
- 期望：先提示错误，等几秒钟再跳转登录页，交互更友好。
- 涉及文件：`src/utils/request.ts`。

### 根因分析

响应拦截器两处 401 分支（业务码 `res.code === 401`、HTTP `status === 401`）都是「`logout()` + 立即 `window.location.href = '/login'`」：

1. 提示缺失：401 分支直接跳走，既没有 `message.error`，用户也来不及看清；
2. **即使加了延迟也会失效**：`src/router/guard.tsx` 的 AuthGuard 依据 `useUserStore` 的 `token` 判断，`logout()` 清空 token 的瞬间就会 `<Navigate to="/login" replace />`，把页面立刻跳走。因此延迟跳转必须把 `logout()` 一起推迟，延迟期间保持登录态。

### 解决方案

在 `src/utils/request.ts` 中抽出统一的 401 处理函数 `handleUnauthorized(msg?)`，两个 401 分支都改走它：

- **先提示**：`message.error({ content: msg || '登录已失效，即将跳转到登录页', duration: LOGIN_REDIRECT_DELAY / 1000 })`，后端返回 message 时优先展示后端文案，否则用兜底文案（含「即将跳转」提示，让用户预期到后续跳转）；
- **再延迟跳转**：`window.setTimeout(..., LOGIN_REDIRECT_DELAY)`，默认 `LOGIN_REDIRECT_DELAY = 2000`（毫秒，可调）；
- **延迟期间不清 token**：`logout()` 放到定时器回调里，避免 AuthGuard 在提示展示期间就把页面跳走（关键点）；
- **并发去重**：新增模块级 `redirectTimer`，非空即表示已在跳转流程中，多个请求同时 401 时只提示一次、只登出一次、只跳转一次；回调里先重置为 `null` 再判断路径；
- **登录页不刷新**：回调中若 `window.location.pathname` 已含 `/login`（如登录接口自身返回 401，如账号密码错误），只保留错误提示，不再整页刷新清空用户输入；路径判断放在 `logout()` 之前，因为清 token 后 AuthGuard 会立即重定向、届时取不到原路径。

非 401 分支（业务码失败 / 非 401 的 HTTP 错误）行为完全不变。

## 任务2：机构服务页直接用「机构服务列表」平铺字段，去掉服务池 / 分类拼装

### 任务描述

- 用户指出：`InstitutionServiceRow` 已平铺返回 `service_name`、`service_category_name`、`service_type`、`price`、`price_override`、`unit`、`status`，因此 `src/pages/service/institution/index.tsx` 只需「按当前选中机构调 `getInstitutionServiceList`」渲染右侧列表，无需再调 `serviceApi.getServices` 与 `serviceApi.getServiceCategories` 拼装。
- 涉及文件：`src/pages/service/institution/index.tsx`。

### 根因分析（已用后端实测确认）

- 原实现只把关联行当「只有 service_id」用，于是额外拉了服务池 + 分类两份全量数据（`page_size: 100`）做 Map 拼装；服务池分页外的服务会降级显示为「服务 {id}」，分类显示「—」。
- 实测后端（测试环境 `GET /api/v1/admin/institutions/10/services`）返回：
  `{"id":24,"institution_id":10,"service_id":12,"service_name":"针灸服务1","service_category_id":2,"service_category_name":"康复理疗","service_type":1,"is_home_service":1,"price":10,"price_override":0,"unit":"yuan","status":1,...}`
  即服务名称、分类、服务方式、价格、单位均已平铺，页面自取即可。
- 仓库内 `src/pages/institution/components/ServicesTab.tsx` 本来就是这一口径（直接用 `record.service_name` / `service_category_name` / `service_type` / `price`），本次与该口径对齐。

### 解决方案

- 删除本地拼装类型 `InstitutionService`、`poolMap` / `catMap` 状态与「服务池 + 分类」`useEffect`，一并移除 `serviceApi` 引用；`services` 直接用 `InstitutionServiceRow[]`。
- 列与筛选改用平铺字段：服务项目 = `service_name` + `service_category_name`；服务方式 = `service_type`（沿用 `serviceTypeText`）；机构价 = `price_override || price`（新增 `resolvePrice`，0 表示沿用集团价）+ `unit`；状态 = `instServiceStatusText[status]`。
- 搜索框文案由「搜索服务名称、项目编码」改为「搜索服务名称、服务分类」（接口未返回 code 字段）；下架确认弹窗的副标题由原来的 `service_id` 改为 `service_category_name`。
- 抽出 `loadServices(institutionId)`：接口② 的 `useEffect` 与「上下架成功后刷新」共用同一份逻辑（原先刷新分支还重复了一遍拼装代码）；用 `serviceSeq` 请求序号替代原 `cancelled` 标记，防止快速切换机构时旧响应覆盖新列表。

## 任务3：机构服务列表接入接口分页，筛选条件下推接口 + 当前页本地兜底过滤

### 任务描述

- 用户要求：机构的服务列表需要翻页，每次切换机构时把 `page` 重置为 1；`institutionApi.getInstitutionServiceList` 返回 `{ list, total }`（服务端分页）。
- 决策（用户选定）：筛选条件下推接口（`keyword` / `service_type` / `status` 全传）+ 对当前页结果再做一次本地兜底过滤。
- 涉及文件：`src/pages/service/institution/index.tsx`、`src/api/modules/institution.ts`。

### 根因分析（已用后端实测确认）

- 改前页面固定请求 `page: 1, page_size: 10`，响应里的 `total` 被丢弃，表格也没有分页器 —— 已接入服务超过 10 项时看不到剩余数据（工作区里 `page/pageSize/total/setPage` 是被引用但未定义的半成品，`npx tsc --noEmit` 报 4 处 `Cannot find name`）。
- 后端分页能力实测（`GET /api/v1/admin/institutions/10/services`）：
  - `page=1&page_size=2` → `list` 2 条、`total=3`；`page=2&page_size=2` → `list` 1 条（id 26）、`total=3`，翻页数据不重复 ⇒ 分页可用。
  - `keyword=针灸`、`service_type=2`、`status=9` **均被后端忽略**（仍返回全部 3 条）⇒ 筛选参数先按契约下推，同时必须保留当前页本地兜底过滤，否则筛选框会完全失效。

### 解决方案

- `src/api/modules/institution.ts`：`getInstitutionServiceList` 参数类型的显式声明补全为 `service_id / service_type / status`（`keyword` 来自 `ApiPageParams`），并注明后端当前仅实现 `page / page_size`。
- `src/pages/service/institution/index.tsx`：
  - 新增分页状态 `page`（默认 1）、`pageSize`（`DEFAULT_PAGE_SIZE = 10`）、`total`（取接口响应）。
  - `loadServices(institutionId, targetPage, targetPageSize, filters)`：把分页与筛选条件一并下推，成功后 `setServices(res.list)` + `setTotal(res.total)`；失败时列表与总数归零。
  - 切换机构：接口② 的 `useEffect` 里先 `setPage(1)` 再请求第 1 页。
  - 查询 / 重置：`applyFilters`、`handleReset` 同样回到第 1 页并重新请求；新增 `handlePageChange`（翻页 / 改每页条数，保持当前筛选条件）。
  - 上下架成功后刷新：改为保持当前页与筛选条件（`loadServices(selectedId, page, pageSize, applied)`），不再固定回第 1 页。
  - 分页器接 `current / pageSize / total / onChange / showTotal`（`total` 来自接口）；`filteredServices` 保留为当前页兜底过滤并加注释说明原因。
  - 清理死代码：删除已不再使用的 `InstitutionSummary` 接口与"回填左侧机构聚合统计"逻辑；`ArrowRightOutlined` 因「进入机构详情」按钮被注释而不再是有效使用，从导入中移除并留注释提示。
