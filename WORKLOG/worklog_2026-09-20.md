## 任务1：退款单 status=8（待财务审批）时列表页 / 详情页提供审批入口

### 任务描述

- 需求：当退款单 `status === 8`（待财务审批）时，退款列表页与退款详情页展示「审批」入口，点击弹出审批表单。
- 现状：`refundApi.approveRefunds`（POST `/admin/refunds/:id/approve`，入参 `approve/opinion/refund_amount/refund_channel`）已定义但页面未接入；列表与详情均无审批入口；详情页状态文案缺 8（待财务审批）。

### 解决方案

- **新增 `src/pages/refund/components/RefundApproveModal.tsx`（列表 / 详情共用审批弹窗）**：
  - 表单字段：审批结果（通过 / 拒绝，单选按钮必填）；通过时显示「实际退款金额（元）」（必填，默认申请全额，`extra` 提示申请金额）与「退款渠道」（必填，枚举：原路退回 / 微信 / 支付宝 / 银行卡 / 线下转账）；审批意见（拒绝时必填，通过时选填，自定义 validator 实现）。
  - 提交：`approveRefunds(refund_id, ...)`，金额由「元」换算为「分」（`Math.round(yuan * 100)`）对齐后端契约；拒绝时金额传 0、渠道传空串。
  - 打开时按目标退款单重置表单（默认通过、金额默认申请全额）；提交中禁止关闭；成功后 `message.success` 并回调父级刷新。
- **`src/pages/refund/list.tsx`**：操作列 width 90 → 120，`status === 8` 时追加「审批」link 按钮（与「查看」并存）；页面挂载 `RefundApproveModal`，`onSuccess` 刷新当前页列表与顶部统计。
- **`src/pages/refund/detail.tsx`**：`REFUND_STATUS_TEXT` 补 `8: '待财务审批'`；右上角操作区在 `status === 8` 时展示主按钮「审批」；挂载 `RefundApproveModal`，`onSuccess` 重新拉取退款详情。
- **状态色**：`list.less` / `detail.less` 的 `.refund-status--8` 与 `--1` 同为警示橙（待处理语义）。

## 任务2：财务对账拆分为「账单汇总 / 渠道流水」两个子菜单并按 finance.ts 契约实现

### 任务描述

- 需求：左侧导航「财务对账」下分两个子项：账单汇总、渠道流水；按 `finance.ts` 已定义的接口实现页面；账单汇总含列表页，列表「查看详情」进入详情页，`detail_lines` 仅在详情页展示。

### 解决方案

- **路由（`src/router/routes.tsx`）**：`/finance` 子路由改为三项——`''` 账单汇总、`channel-log` 渠道流水、`detail/:id` 对账详情（`hideInMenu: true`）；菜单由 menu.tsx 自动生成，无需改菜单组件。
- **新增 `src/pages/finance/reconcile/index.tsx`（账单汇总列表）**：
  - 接口：`getReconciliations`（分页 + reconciliation_type / status / start_date~end_date 筛选，日期按 `YYYY-MM-DD` 字符串下推）；
  - 顶部统计：全部 / 对账中 / 已平账 / 有差异，各状态 `page_size=1` 取 total（与退款列表同一轻量方案）；指标卡按 `metric-card.less` 文档约定使用全局 `status--*` tone 类；
  - 列：对账批次+周期、支付渠道、对账类型、平台金额、渠道金额、差异金额（非零标红）、平台/渠道笔数、对账状态 pill、操作（查看详情 → `/finance/detail/:id`；非已平账单据提供「平账」入口，`finishReconciliation` + 二次确认）。
- **新增 `src/pages/finance/reconcile/detail.tsx`（对账详情）**：
  - 头部：`getReconciliation(id)`；汇总卡 + Descriptions（批次号 / 渠道 / 类型 / 周期 / 平台 / 渠道 / 差异金额 / 笔数）；
  - 差异明细：`getReconciliationDetails(id)` **分页**拉取（`detail_lines` 仅本页展示），支持匹配状态筛选（1-完全匹配 2-金额不一致 3-仅渠道有 4-仅平台有），列含订单、渠道流水号、平台/渠道金额、差额（非零标红）、匹配状态 pill、备注；
  - 非已平账单据右上角提供「平账」按钮。
- **新增 `src/pages/finance/channel-log/index.tsx`（渠道流水）**：`getPaymentChannelLogs`（分页 + status / start_time~end_time 秒级时间戳筛选）；列含渠道流水号、渠道、关联订单、交易金额、手续费、状态、对账时间、创建时间；关键字（流水号 / 订单ID）后端无参数，当前页本地兜底过滤（与退款列表同策略）。
- **旧页处置**：原 `pages/finance/list.tsx`（纯 mock，引用了 finance.ts 中已不存在的 `ReconcileStatus`，编译报错）改为兼容 shim（`export { default } from './reconcile'`），旧 `list.less` 不再被引用（删除命令因审批超时未执行，待手动删除）。
- **样式**：每页同名 less，全部使用 variables/mixins 变量；`filter-bar` / `list-card` / `metric-cards` 复用公共类。
