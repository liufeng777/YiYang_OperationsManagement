## 任务5：AddAccount 表单 bug 与必填红星检查

### 任务描述

- 用户需求：检查 `AddAccount.tsx` 表单是否有 bug；并说明 `required: true` 项为何未显示左侧红星。

### 检查结论与修复

- **红星不显示原因**：`<Form>` 上设置了 `requiredMark={false}`，antd 据此隐藏必填星号。移除该属性后，`required: true` 项（登录账号/密码/昵称/手机号/所属角色）会自动在 label 左侧显示 `*`。
- **表单 bug（avatar_url 受控冲突）**：原实现 `<Form.Item name="avatar_url">` 直接包裹受控 `Upload`（`fileList={avatarList}`），Form.Item 会把注入的 value 透传给 Upload 并拦截其 onChange 把 fileList 写入 `avatar_url`，覆盖 handler 设置的 dataURL 字符串。已解耦：Upload 置于无 name 的 `<Form.Item label="头像">`，`avatar_url` 改为独立隐藏字段，仅由 `handleAvatarChange`/`handleRemoveAvatar` 写入。
- 其余检查项（`status` 1/9 双向映射、邮箱 email 校验、`role_ids` 多选 min:1 校验、`useEffect` 打开时重置）均正常，无 bug。

| --- | --- | --- |

## 任务18：modal.confirm okButtonProps color:'danger' 未生效的修复

### 任务描述

- 用户：`modal.confirm({ okButtonProps: { color: 'danger' } })` 删除按钮未变危险红。

### 原因（antd v6 Button 颜色计算）

antd v6 Button 的颜色由 `color` 与 `variant` 共同决定，优先级逻辑（`es/button/Button.js`）：

```js
if (color && variant) return [color, variant];   // 仅当 color 与 variant 同时提供才走这里
if (type || danger) { /* 用 type 映射的(color,variant)，若 danger=true 强制 color=danger */ }
```

`Modal.confirm` 的确认按钮由 `okType`（默认 `'primary'`）经 `convertLegacyProps` 注入 `type:'primary'`。用户只传 `color:'danger'`（无 `variant`），命中第二个分支：因存在 `type:'primary'`，按钮按主色渲染，`color:'danger'` 被忽略。

### 解决方案

将 `okButtonProps` 由 `{ color: 'danger' }` 改为 `{ danger: true }`：
- Button 收到 `danger=true` 后，在 `type/danger` 分支里 `danger=true` 强制返回 `color='danger'`，按钮变危险红。
- 该写法与项目其它处（account/role/templates/announcements）一致，type-check 通过。
