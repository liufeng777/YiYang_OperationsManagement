## 任务1：机构服务页按真实接口逻辑重构（先拉机构列表，切换机构按 id 拉服务列表）

### 任务描述

- 用户需求：真实接口逻辑是——先获取机构列表渲染页面左侧机构列表；切换机构时将机构 id 传给接口，获取对应机构的服务列表。按此逻辑修改 `src/pages/service/institution/index.tsx` 并重新 mock 数据。

### 解决方案

- **mock 拆分**：原 `mockInstitutions`（机构内嵌 services）拆为两张表——`mockInstitutionList: InstitutionSummary[]`（机构列表，含 serviceCount / onlineCount / offlineCount / orderCount30d 聚合统计，供左侧列表展示）与 `mockServiceMap: Record<number, InstitutionService[]>`（按机构 id 的服务列表）；机构与服务 id 统一改为 number
- **模拟接口**：`fetchInstitutions()` 与 `fetchInstitutionServices(institutionId)`（300ms delay 模拟异步，TODO 注释标明替换为 institutionApi / serviceApi.getInstitutionServices）
- **组件数据流**：
  - 接口①：mount 时拉机构列表（`instLoading`），完成后确定初始选中（URL `?institution=` > store 记忆 > 第一项）
  - 接口②：`selectedId` 变化时携带机构 id 拉服务列表（`serviceLoading`、清空勾选、竞态 cancelled 保护）
  - URL 带参跳转改为机构列表就绪后生效；id 数值化后与 institution 详情页路由对齐
- **状态变更**：新增 `applyServiceStatus(ids, nextStatus)` 统一入口——更新当前机构服务列表，并同步左侧机构 online/offline 聚合统计；批量启用/停用、单条停用（原因≥5字）、单条启用均走该入口
- **顺手修复的存量问题**：
  - 勾选状态判断 `selectedItems` 原来错误地 filter 机构数组（`data`），改为 filter 当前服务列表（`services`）——此前批量按钮逻辑实际失效
  - `modal.confirm` 未解构（只有 `message`）→ `App.useApp()` 补 `modal`
  - 预约状态统一为 1 可预约 / 9 已停用（对齐 DTO CommonStatus），筛选项与表格渲染、左侧统计口径一致（原 1/2/3 与 statusText 1/9 不匹配）
  - 服务方式筛选改由 `typeText` 生成（去掉残留的"陪同"与 label 为数字的选项）
- **loading/空态**：机构列表加载 Spin、表格 `loading={serviceLoading}`、机构未就绪时详情卡头与按钮兜底
