## 任务：推荐列表按实测接口重渲染 + 修复表格逐行加载

### 需求描述

1. `ReferralItem` 按后端实测结构重新渲染推荐列表（biz_id/biz_name/referral_code/user_name/user_id；奖励状态语义改为 1-未奖励 2-已奖励 3-已过期 9-作废）；接口实际返回标准分页结构 `{ list, total }`；
2. 排查推荐列表表格「一行一行加载」的问题。

### 逐行加载根因

上一版把 antd Tabs 作为 PageContainer fixed 的唯一子级并包了全部内容，打断了固定高度链：
`.fill-table` 容器高度不再受视口约束而由内容撑开，FillTable 的 ResizeObserver/MutationObserver
在表格增高的过程中反复触发 `scroll.y` 重算与表格重渲染，形成「测量 → 重渲染 → 再测量」反馈回路，
肉眼即逐行渲染。修复：Tabs 仅作分段导航（items 不带 children），Tab 内容条件渲染为
`.referral-page` 的直接子级，恢复 `list-card--fill` 标准高度链，`scroll.y` 一次测量即稳定。

### 变更内容

- `src/api/modules/reward.ts`：`ReferralItem` 对齐实测字段；`getReferralList` 返回 `ApiPageResult<ReferralItem>`；筛选入参 reward_status 注释同步新语义；
- `src/pages/member/referral/index.tsx`：列改为 用户（姓名+ID）/ 推荐码 / 事件类型 / 业务类型 / 关联业务（biz_name，兜底 #biz_id）/ 奖励状态（1/2/3/9 四态色）/ 状态 / 创建时间；改服务端分页（fetchList(page, filters, size)，查询/重置/翻页/改条数均下推后端）；Tabs 改导航-only 布局；

## 字体改为 CDN 在线引入（精简构建产物）

**时间**：2026-09-29 晚间

### 需求背景

构建产物 `dist/assets` 中 672 个文件有 588 个是 `@fontsource/noto-sans-sc` 打出的字体子集（约 120 个子集 × 3 字重 × woff/woff2 双格式，共约 17MB）。用户确认改为在线引入。

### 变更内容

1. `src/main.tsx`：删除 `@fontsource/noto-sans-sc` 的 400/500/700 三个 css 引入。
2. `index.html`：改为 CDN 在线引入（`fonts.loli.net`，Google Fonts 国内镜像），含 `preconnect`，字重 400/500/700，`display=swap`。
3. `package.json`：卸载 `@fontsource/noto-sans-sc` 依赖。
4. 字体栈（`antdTheme.ts` / `variables.less` 的 `'Noto Sans SC', -apple-system, ..., 'PingFang SC', 'Microsoft YaHei', sans-serif`）保持不变——CDN 加载失败时自动回退系统字体。

### 验证结果

- `npm run build`（含 `tsc --noEmit`）✅ 通过；
- `dist/assets` 文件数 **672 → 84**，其中字体文件 **0 个**；JS/CSS 分包不变，构建耗时约 1.2s。

### 取舍说明

CDN 引入后产物精简、构建更快；代价是**内网/离线部署环境**下 Noto Sans SC 加载失败会回退到系统字体（PingFang SC / 微软雅黑）。如未来需纯内网部署，可改回本地字体包或私有化托管字体文件。
