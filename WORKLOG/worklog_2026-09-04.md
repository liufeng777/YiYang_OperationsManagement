## 任务1：服务详情页按 ServiceItem DTO 重构（套餐 Table + cover_url/description 落字段）

### 任务描述

- 用户需求：根据最新 `ServiceItem` DTO 修改服务详情页代码——① 服务规格与套餐改用 antd Table 渲染；② 患者端封面图存 `cover_url`；③ 详情图片与服务内容统一用富文本编排，存 `description` 字段。

### 解决方案

- **表单字段对齐 DTO**：`category` → `category_id`（number，选项过滤掉 id=0「全部服务」）、`mode` → `service_type`（number，选项 value 转 Number）、`duration` 改 InputNumber（分钟）；编辑回填改用 `category_id / service_type / is_consumable_supported / status(1|9)`，修复全部存量类型错误
- **套餐改 Table**：`PackageItem extends Package`（`count / price / price_with_consum`），套餐名称由次数派生（1 次 = 单次服务，N 次 = N次套餐）；自定义 div 表格替换为 antd `Table`（rowKey/size small/无分页），弹窗表单字段同步改为 `count / price_with_consum /price`；保存时映射为 DTO `Package[]`（关闭套餐时仅保留「单次服务」）
- **患者端展示内容**：
  - 封面：`handleCoverUpload` 走 `uploadApi.uploadFile`，成功存服务器 url 到 `coverUrl`（保存时写入 `cover_url`），接口不可用降级本地预览
  - 详情图片 + 服务内容：移除 ImageSortGrid 与 TextArea（及此前的 Drawer 入口），改为卡片内**内联 RichTextEditor**；`onChange` 将 ProseMirror JSON `JSON.stringify` 存入 `description` state；编辑场景用 `detailLoaded` 控制编辑器挂载时机，保证初始 JSON 生效；`descriptionContent` 解析失败时按 HTML 兼容
- **保存组装**：`handleSave` 按 `ServiceSaveBody` 组装完整 payload（含 cover_url、description、packages、service_type、status 1/9），console.log 留 TODO 接 `createService / updateService`
- **联动修复**：`service.ts` 的 `getService` 返回类型 `ServiceDTO` 未定义 → 改 `ServiceItem`；`service/institution/index.tsx` 引用已删除的 `ServiceMode` → 改为页内本地类型
- **样式**：`.editor-upload--detail` / `.editor-content__textarea` 规则替换为 `.editor-upload--richtext`（flex:1 占满封面后剩余宽度），响应式同步
