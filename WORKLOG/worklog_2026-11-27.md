# 工作日志 - 2026-11-27

## 任务：按详情接口实际返回重构退款详情页展示

### 需求描述

退款详情接口返回了订单、机构、服务项目、会员 / 下单账号、联系人、金额构成、履约次数、`work_orders` 履约摘要等字段，且审批与退款渠道记录需要更直观的时序展示；要求按实际数据优化页面展示，部分区块使用 Timeline 渲染。

### 变更内容

- `src/api/modules/refund.ts`：按接口实际返回补齐 `RefundItem`（`institution_name`、`service_name`、`member_name`/`user_name`、`contact_name`/`contact_phone`、`total_amount`/`discount_amount`/`paid_amount`、`service_count`/`served_count`、`is_use_consumables`、`order_status`、`created_at`、`remark`、`work_orders` 等）；把审批记录、渠道记录、履约工单抽为 `RefundApproval` / `RefundChannelLog` / `RefundWorkOrder`；`record_id` 修正为 `number`；显式声明金额字段由接口以「元」字符串返回（`RefundAmount`）。
- `src/pages/refund/detail.tsx`：
  - 修正金额单位：审批记录的核定退款金额不再除以 100（接口返回 `"150.00"` 即 150 元），与列表 / 订单口径一致。
  - 新增「退款进度」Timeline：把申请提交（`applied_at`）、业务 / 财务审批（`approvals`）、渠道退款执行（`refund_channel_logs`）、退款到账（`refunded_at` 或 `status=4`）合并为按时间升序的单一时间线，节点含结果徽标、审批人、核定金额、渠道、审批意见、渠道单号与失败原因；流程未结束时追加「当前状态」节点并标注待处理环节。
  - 「退款单信息」保留为 Descriptions，改为展示退款类型 / 退款方式 / 关联订单 / 审批通过人 / 审批通过时间 / 退款渠道（由最后一条通过审批派生）/ 退款时间 / 申请时间 / 退款原因 / 备注。
  - 新增「订单与服务信息」Descriptions：订单状态、服务机构、服务项目、服务对象与下单账号、联系人与电话、下单时间、服务次数（已消费 / 总次数并高亮剩余次数）、是否使用耗材、订单原价 / 优惠 / 实付 / 本次退款。
  - 新增「履约记录」Timeline：按 `order_seq` 展示 `work_orders` 的服务次序、工单号、工单状态（优先 `wo_status_name`）、服务人员、期望上门 / 完成 / 取消时间。
  - 移除详情页对 `ORDER_REFUND_TYPE` 之外额外订单请求的依赖（`orderApi.getOrder`），详情接口已直接返回履约次数与工单摘要，减少一次请求；摘要卡新增「退款金额占订单实付比例」提示。
- `src/pages/refund/detail.less`：重写为摘要 + 两栏（退款单信息 / 退款进度）+ 全宽订单信息 + 履约记录；新增进度与履约 Timeline 节点样式（标题 + 状态徽标 + 时间 + 字段网格 + 说明），右栏 400px，1200px / 720px 断点折为单栏；移除不再使用的渠道日志卡片样式。
- `src/pages/refund/components/RefundApproveModal.tsx`：`amount` 类型放宽为 `number | string`，表单默认值统一 `Number(refund.amount)`。
